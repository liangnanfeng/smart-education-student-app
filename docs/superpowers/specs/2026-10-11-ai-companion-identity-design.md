# AI 伙伴统一形象与登录转场设计

**日期：** 2026-10-11  
**状态：** 已与产品负责人逐项确认，待实施计划审批

## 目标

让积分商城成为学生调整 AI 伙伴形象、服饰和装饰的唯一入口；同一学段内，登录页、应用内右下角伙伴、商城预览、个人页和后续所有 AI 入口始终显示完全一致的搭配。每次成功登录时，登录页顶部的伙伴平滑跑入主界面右下角位置。

本次保持现有登录、注册、找回密码和学段切换功能不变，也不接入真实 AI 服务或后端账号服务。

## 已确认的产品规则

### 学段与默认搭配

- 同一账号的小学端与中学端分别保存搭配，互不覆盖。
- 首次使用小学端时，学生已拥有并装备 **绒桃 Momo**。
- 首次使用中学端时，学生已拥有并装备 **云宝 Nimbo**。
- 首次使用时没有服饰和装饰。
- 每套搭配最多装备一项形象、一套服饰和一项装饰。

### 商城调整方式

- 学生先打开商品详情，查看大预览后购买。
- 购买成功后，商品加入当前学段的“已拥有”列表，并弹出“现在换上吗？”。
- 学生可以立即装备，也可以保留原有搭配；选择暂不更换不会改变当前展示。
- 服饰和装饰也可装备，且会同步显示到登录页与应用内伙伴。
- 原有设置页的 emoji 皮肤选择将不再是第二个更换入口，改为引导学生前往积分商城调整伙伴。

### 统一展示

- 所有出现 AI 的位置都读取当前学段已装备的搭配：登录页、右下角伙伴、商城预览、个人页及以后新增的 AI 入口。
- 统一展示组件必须在固定安全框内等比例缩放、居中和裁切角色；不得拉伸图片。
- 角色、服饰与装饰作为一个视觉组合同时缩放、移动和切换，避免不同角色比例造成遮挡、错位或明显跳变。

### 互动

#### 登录前

- 顶部大 AI 展示当前学段的已装备搭配。
- 轻点 AI：播放轻微眨眼、挥手或跳跃，并显示一条简短欢迎语。
- 长按 AI：打开受限游客对话浮层。
- 游客对话只允许简单问答，不读取账号、不保存长期记忆、不执行应用控制；现阶段提供安全的演示回复，后续接入 API 时再添加模型能力与年龄适配审核。

#### 登录后

- 右下角伙伴展示同一套已装备搭配。
- 轻点伙伴打开快捷互动和语音入口；长按进入完整聊天界面。
- 完整聊天继续遵循既有产品约定：小学端采用好奇的冒险伙伴与活泼游戏搭子语气；中学端采用理性的科学探索搭档与未来科技助手语气。
- AI 应理解大部分自然语言应用操作；遇到模糊或错误指令时应委婉澄清。
- 普通操作可直接执行；中风险操作先显示预览并要求屏幕确认；高风险操作要求密码确认。
- 学生可在设置中调整 AI 位置、建议偏好及相关设置。

### 账号模拟存储

- 原型阶段按当前浏览器中的模拟登录账号持久化搭配数据。
- 刷新页面、退出后再次登录时，两个学段各自的搭配仍然保留。
- 存储模型预留账号标识和服务端同步边界；后续接 API/后端时，用远端读写替换本地持久化而不改变页面消费方式。

## 技术与组件设计

### 搭配数据模型

在全局应用状态中，以学段为键维护伙伴档案。每一项档案包含：

- `owned`：形象、服饰、装饰的已拥有商品 ID 集合；
- `equipped`：当前装备的形象 ID、可空服饰 ID、可空装饰 ID；
- `position`：现有右下角伙伴的可调整位置配置；
- `version`：用于未来数据迁移的版本标记。

现有旧 emoji `aiSkin` 状态会迁移到统一搭配模型的兼容层，避免旧页面读取失败。所有写入都通过应用状态层的明确 action 完成，而商城、登录页、伙伴和设置页仅消费同一套选择器结果。

### 伙伴外观组件

创建一个可复用的伙伴展示组件，输入当前学段搭配、展示尺寸、互动状态和可选动画状态。它负责：

- 按角色 sprite 图的首帧或互动帧渲染形象；
- 将服饰与装饰按预定义锚点叠加；
- 根据展示容器采用 `object-fit: contain` 等比例缩放策略；
- 提供小、中、大三种安全展示框，分别供右下角、商城／个人页、登录页使用；
- 在资源缺失时显示默认形象并记录可诊断的开发信息，不阻塞登录。

商品元数据需包含展示锚点或适配类型，使不同体型角色能使用稳定的服饰、装饰布局。第一期仅支持当前商城中与对应学段兼容的商品；不兼容商品不得出现在该角色的装备候选中。

### 商城

商城的形象、服饰、装饰保留为三个大分区。形象商品详情展示大预览、拥有状态和装备状态；服饰、装饰使用同样的购买／装备规则。购买之后仅在学生明确选择“现在换上”时写入装备状态。

设置页不再维持独立皮肤数据，而是提供“前往积分商城调整伙伴”的入口。

### 登录页与游客互动

登录页根据当前选中的学段读取搭配，所以切换小学／中学时，顶部大形象和文案一同更新。登录账号、密码、找回密码、注册与学段选择保持现有行为。

游客互动浮层是本地受限体验：有明确的未登录提示、有限的安全演示对话和关闭入口。其界面边界与登录身份完全隔离，不得创建长期记忆、写入账号数据或执行语音控制。

### 登录转场

1. 点击登录后，在登录页记录伙伴展示框的实际屏幕矩形和当前搭配标识。
2. 主界面挂载时，伙伴组件测量右下角目标停靠位。
3. 使用 fixed 动画图层将同一套组合从起点沿平滑弧线运动到目标位置，持续约 0.7–0.9 秒，并同步从大展示框平滑缩放为浮动伙伴大小。
4. 动画期间主界面淡入；到达后动画图层卸载，由正式右下角伙伴接管互动。
5. 每次成功登录播放。若用户启用减少动态效果、资源加载异常、直接刷新或无法获取起点／终点矩形，则跳过动画并直接显示正式伙伴，不阻塞登录。
6. 更换搭配只即时刷新展示；不会在已登录状态重复播放该登录转场。

## 错误处理与安全边界

- 本地持久化数据缺少字段、格式损坏或包含已下架商品时，回退到该学段默认形象、无服饰、无装饰，并保留可恢复的正常登录流程。
- 未拥有商品不能装备；跨学段商品不能出现在当前学段的装备候选中。
- 资源加载失败时，展示默认伙伴，不影响商城浏览、登录或主界面使用。
- 游客对话不接触账号、成长数据、聊天历史、位置或应用控制接口。
- 后续 API 接入必须在服务端和客户端两层实施中小学生内容安全、权限确认和审计规则；本次不伪造真实语音或模型调用。

## 测试策略

- 全局状态：默认档案、两学段独立保存、购买、选择暂不更换、立即装备、刷新恢复、无效持久化回退。
- 商城：按学段过滤、商品详情预览、已拥有／已装备状态、购买确认与装备写入。
- 伙伴展示：三种尺寸不拉伸、角色与服饰／装饰同步渲染、缺失资源回退。
- 登录页：学段切换更新伙伴、点击互动、长按打开受限游客对话、原有登录字段和链接不回归。
- 转场：登录成功时发起一次动画；减少动态效果／缺少起点时直接显示伙伴；结束后正式伙伴可互动。
- 完整回归：现有注册、找回密码、商城筛选、AI 位置和底部导航测试仍应通过；不修改用户已有的无关测试预期。

## 非目标

- 本次不接入真实 AI／语音 API，不实现长期记忆、云端聊天记录或实际语音识别。
- 本次不实现真实支付、积分扣减或真实后端账号认证。
- 本次不新增未确认的服饰、装饰商品，也不改变已存在的学段视觉主题。
